# 门铃 · astrbot_plugin_doorbell

把两个目录当收发台：新请求单落地，通知处理方；回执落地，通知发起方。

只负责叫一声——不伪造事件，不强行唤醒。

## 它做什么

- 监视 `request_dir`，新单落地即推一条消息到 `target_umo`
- 监视 `done_dir`，回执落地即推一条到 `reply_umo`
- 轮询间隔在秒级，落盘即响，不必等下一次对话

单子就是 JSON 文件，六个字段随你写，插件不校验内容、不改写内容。

## 它不做什么

这一节是 v0.3.0 特意划出来的：

- **不伪造事件。** 早先版本里有个 `_wake()`，会构造伪事件往事件队列里塞，试图「叫醒」对方。这条路被删掉了——伪事件过不了平台身份校验，塞进去也是白塞，还容易让人误以为路通了。
- **不写死会话。** 推给谁由配置决定，代码里没有硬编码的 UMO。
- **不阻塞消息。** 通知失败就记日志，不影响正在进行的对话。

它只相信一件事：文件落地本身就是信号。

## 安装

```text
放进 AstrBot 的 data/plugins 目录，重载插件。
```

## 配置

- `enable`：总开关
- `request_dir` / `done_dir`：两个目录，可写绝对路径，也可写相对 AstrBot 数据目录的路径（如 `handoff/request`）
- `target_umo` / `reply_umo`：两个方向分别推给谁

首次运行会自动建目录。

## 已知限制

- 文件监视是轮询，不是 inotify，秒级延迟是常态
- 只认 JSON，扩展名无所谓；写坏的文件会被跳过并记一条日志
- 它是「喊人」用的，不是「传数据」用的；大文件请自己管
