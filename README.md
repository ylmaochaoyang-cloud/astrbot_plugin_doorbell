# 门铃 · astrbot_plugin_doorbell

把两个目录当成收发台：新请求单落地就通知处理方，回执落地就通知发起方。

适合这种场景：一个 agent 在这里干活，另一个在别处等消息；两边谁也看不见对方的聊天窗口，但都能读写同一个目录。目录一动，门铃就响。

## 它做什么，不做什么

做一件事：盯着两个目录，出现新的 `.json`，把里面几个字段拼成一句话，推到配置的会话。

不做三件事：不伪造平台事件、不强行唤醒 agent、不替你确认单子。

这三点是踩过坑才写进来的——往 WebChat 里塞一条假事件，回复没有出口；往 QQ 那头发，过不了平台校验。真要唤醒，用官方的 `POST /api/v1/chat`。

## 单子的格式

一个文件就是一张单，字段自选，缺了用占位符：

```json
{"id": "20261102-1", "intent": "换封面", "action": "generate", "target": "assets/", "note": "要暖色"}
```

回执：

```json
{"id": "20261102-1", "ok": true, "result": "生成 3 张，选了第 2 张"}
```

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `request_dir` | `handoff/request` | 请求单目录；绝对路径，或相对 AstrBot 数据目录 |
| `done_dir` | `handoff/done` | 回执目录 |
| `target_umo` | 空 | 新单推给谁；空则只记日志 |
| `reply_umo` | 空 | 回执推给谁 |
| `interval_seconds` | `1.0` | 轮询间隔，目录扫描很轻 |

启动时会把已有文件记为“已见”，不会把历史单子全推一遍。

## 指令

`/handoff`：看看两头各有几张单。

## 依赖

AstrBot 4.29 及以上，无第三方包。
